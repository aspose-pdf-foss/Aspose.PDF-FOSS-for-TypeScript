# EPUB output — Calibre verification

`Document.ToEpub` is tested for **structural** conformance to EPUB 3 by
`test/epub-package.test.ts` and `test/epub-export.test.ts`. Those tests prove
the archive says the right things about itself; they cannot prove a reader
opens it. This file records that a real reader does, and exactly how that was
established (`zwto.3`).

Nothing here runs in `npm test`. A test that shells out to Calibre would fail
for everyone who does not have it installed, and the suite is hermetic by
design — the same reason `test/docx-package.test.ts` proves ECMA-376
conformance and says nothing about Word.

## What was verified

| | |
|---|---|
| Reader | **calibre 7.26.0** (`ebook-convert.exe`, Kovid Goyal) |
| Date | 2026-08-18 |
| Fixture | generated by `Document.New()` + `AddMarkdown(..., { tagged: true })`, 2293 bytes |
| Fixture SHA-256 | `13e92f162eb2aac28378e9c71f74b2672eebbaafedf826284ad70b56f9f2ea3c` |

The fixture is a representative book rather than a minimal one: `/Info`
metadata, content before the first heading, two `H1` chapters, an `H2` nested
inside the first, a bullet list, and bold and italic runs.

```bash
# 1. parses, and keeps its content
ebook-convert voyage.epub voyage.txt

# 2. reads the metadata
ebook-meta voyage.epub

# 3. reads the NAVIGATION -- see "What the obvious evidence does not prove"
ebook-convert voyage.epub roundtrip.epub
unzip -p roundtrip.epub '*toc.ncx'
```

| Checked | Result |
|---|---|
| Archive parses | exit 0, no warnings or errors |
| Every content document read | `chapter1.xhtml`, `chapter2.xhtml`, `chapter3.xhtml` |
| Chapters found | `Detected chapter: Chapter One`, `Detected chapter: Chapter Two` |
| Navigation read | round-trip `toc.ncx` carries our three titles |
| Content preserved | front matter, both chapters, the nested `H2`, all list items |
| Metadata | Title `The Voyage of the Beagle`, Author `Charles Darwin` |
| Identifier | `sha256:8fa18592…` — the content-hash fallback, since `Document.New` has no trailer `/ID` |

## What the obvious evidence does not prove

**`Detected chapter:` is not evidence that our navigation document works.**
Calibre infers chapter boundaries by XPath over `h1`/`h2` in the content
documents, so those two lines appear whether or not `nav.xhtml` is well-formed,
correctly referenced from the manifest, or even read at all. Taking them as
proof would leave the nav — the actual deliverable of `zwto.2` — unverified
while looking verified.

The round trip is the check that distinguishes the two: converting EPUB → EPUB
makes Calibre build its own `toc.ncx`, and our three chapter titles appear in
it. That can only happen if the nav was parsed.

**`Trimming 'EPUB/nav.xhtml' from manifest` is not a defect.** Calibre logs it
when converting to plain text, which needs no navigation. It is Calibre pruning
its own intermediate manifest, not a complaint about ours — and the round trip
above shows the nav was read before being pruned.

## What remains unverified

- **Other readers.** iBooks, Kindle (via conversion), Kobo and the various
  Android readers are untested. Calibre is the most permissive of the common
  readers, so this is a floor, not a ceiling.
- **`epubcheck`**, the official IDPF validator, has not been run. It is a Java
  tool and is not installed here; fetching it would mean a network download,
  which this repo does not do for a build or a test.
- **Fixtures with harder content.** The verified fixture has no images, no
  tables, and no CJK text. `ToEpub` handles all three, and none of them is
  covered by this record.
